# Executive Technical Framing — Wave 121

## ملخص تنفيذي

أَثِيل ليس تطبيق فعاليات بسيطًا، ولا CMS ثقافي، ولا منصة ذكاء مستقلة عن التشغيل.

أَثِيل في صورته الصحيحة هو:

منصة تشغيل وقرار للتجارب والوجهات والبرامج الثقافية والسياحية والتراثية، تجمع بين التشغيل اليومي، الحوكمة، المعرفة، تصميم التجربة، الذكاء القطاعي، وقياس الأثر داخل نظام واحد.

المشكلة الحالية في المستودع ليست غياب الأفكار أو الوحدات، بل اتساع السطح أسرع من انضباط القلب. لذلك الهدف في الموجات القادمة ليس إضافة ميزات متفرقة، بل إعادة ترتيب المنصة لتصبح قابلة للتسليم، والتشغيل، والتوسع، والاستلام من فريق هندسي جديد بدون اعتماد على الذاكرة الشفوية.

## الهدف التجاري

الهدف التجاري في النسخة الأولى ليس بيع أَثِيل كمنصة لكل شيء.

الهدف التجاري الصحيح هو بيع 3 طبقات واضحة:

1. Atheel OS
   - إدارة الجهات
   - المشاريع
   - البرامج
   - المحتوى
   - الاعتمادات
   - المرفقات
   - التشغيل اليومي

2. Atheel Heritage + Visitor
   - إدارة الأصول التراثية
   - السرد
   - الوسائط
   - واجهات الزائر
   - المسارات العامة
   - النشر المنضبط

3. Atheel Intelligence + Governance
   - المعرفة المنظمة
   - البحث الدلالي
   - دعم القرار
   - المراجعات
   - الحوكمة
   - الحزم التنفيذية والتقارير

## الهدف التشغيلي

الهدف التشغيلي هو الوصول إلى منصة يمكنها دعم جهة مؤسسية حقيقية عبر:

- Multi-tenant organization model
- Role-based access control
- Project / program lifecycle
- Heritage asset lifecycle
- Review and approval lifecycle
- Search + knowledge + AI assist
- Public visitor publishing
- Auditability
- Observability
- CI/CD and migration discipline

## مبادئ التطوير الحاكمة

1. لا تطوير خارج product scope المعتمد
2. لا feature work فوق قلب غير مغلق
3. لا fallback إنتاجي في المسارات الحرجة
4. لا UI route جديد بدون workflow وentity وAPI واضح
5. لا ذكاء اصطناعي بلا معرفة، ومصادر، ومراجعة بشرية
6. لا 3D / Twin / XR قبل ثبات النواة التشغيلية والبيانية
7. كل موجة يجب أن تكون قابلة للتسليم بصراحة: ماذا أغلقت، ماذا بقي، وما المخاطر
