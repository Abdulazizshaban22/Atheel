# انتقال أَثِيل من Modular Monolith إلى خدمات قابلة للاستخراج

## الفكرة
المنصة تعمل كنواة تشغيل ثابتة، ومعها وحدات مجال قابلة للتمكين. نبدأ بنظام واحد منظم Modular Monolith ثم نستخرج الخدمات الثقيلة فقط عندما يكون ذلك ذا أثر واضح.

## لماذا لا نفكك كل شيء فورًا
تفكيك واسع مبكرًا ينتج عبء تشغيل عالي ويخلق ظواهر مثل Distributed Monolith. الحل هو استخراج خدمة واحدة ثقيلة، ثم تثبيت أنظمة التتبع والموثوقية.

## نموذج طبقتين
1) Control Plane داخل apps/api
- Auth, Sessions, Policy, Audit, Tenancy, Config
- Approval, Workflows, Delivery packets

2) Application Plane كخدمات منفصلة
- exports-svc للتوليد
- لاحقًا: rag-svc للفهرسة والاسترجاع
- لاحقًا: radar-svc للمسح والتحليل

## قاعدة قرار استخراج خدمة
استخرج خدمة عندما يتحقق معظم التالي:
- حمل CPU أو ذاكرة عالي أو زمن استجابة طويل
- إمكانية تشغيل Stateless أو شبه Stateless
- واجهة عقد واضحة ويمكن اختبارها بسهولة
- يمكن توسيعها أفقيًا دون التأثير على بقية النظام

## ماذا تم تطبيقه فعليًا
- Wave57: استخراج exports-svc
- Wave58: Service Outbox لضمان موثوقية الاتصال وتجنب dual write
