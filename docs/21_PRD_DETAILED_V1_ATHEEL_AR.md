# PRD تفصيلي جدا للنسخة الأولى V1 — منصة أَثِيل

> **ملاحظة تحديث (بعد Wave122):** هذا الـ PRD يصف نطاق V1. النطاق التطبيقي اتسع منذ ذلك الحين
> ليشمل أدمغة قطاعية (Heritage / Destination / Mega-Events)، TwinSpec، Vector RAG، Exports
> Microservice، Queue Observability، و Runtime Hardening. لتفاصيل البنية المعمارية الحالية
> راجع `docs/07_ARCHITECTURE_AR.md` و `docs/architecture/WAVE121_*` و `docs/architecture/WAVE122_*`.
> هذا الملف يبقى مرجعاً تاريخياً لتعريف V1 وقصص المستخدم الأصلية.

## 1) تعريف المنتج
أَثِيل منصة تشغيل ثقافي سعودي تجمع بين تشغيل المشاريع الثقافية، إدارة المحتوى الثقافي، تصميم التجارب، وقياس الأداء، مع طبقة ذكاء اصطناعي تساعد الفرق الثقافية بدل أن تستبدلها.

## 2) هدف النسخة الأولى
إثبات أن المنصة تقلل زمن التشغيل الثقافي وتزيد جودة التجربة والحوكمة داخل جهة واحدة أو مشروع واحد ثم التوسع متعدد الجهات.

## 3) نطاق النسخة الأولى
- إدارة المشاريع الثقافية
- إدارة المحتوى الثقافي
- إدارة التجارب الثقافية
- تسجيل دخول وصلاحيات أساسية
- لوحة مؤشرات تشغيلية أولية
- مساعد AI للمحتوى والتلخيص وإعادة الصياغة

## 4) خارج النطاق (V1)
- التذاكر والمدفوعات
- تطبيق زائر كامل للجمهور
- تكامل ERP/HR
- إدارة أصول تراث عمراني متقدمة (تأتي في V2+)
- GIS متقدم ثلاثي الأبعاد
- ميتافيرس تفاعلي كامل

## 5) شخصيات المستخدمين (Roles)
### 5.1 مدير منصة / Super Admin
يدير المنصة عبر الجهات والخطط والصلاحيات ومؤشرات الأداء العامة

### 5.2 مدير جهة / Org Admin
ينشئ فرق الجهة، المشاريع، سياسات النشر، ويعتمد الصلاحيات

### 5.3 مدير مشروع ثقافي / Project Manager
يدير الخطة الزمنية والتقدم والربط بين المحتوى والتجارب

### 5.4 أمين محتوى / Curator
يبني المواد الثقافية ويطابقها مع الهدف والمرجع والسياق

### 5.5 محرر محتوى / Content Editor
يصيغ النصوص ويرفع النسخ واللغات ويستخدم مساعد AI

### 5.6 مصمم تجربة / Experience Designer
ينشئ التجارب والمسارات والمدة والحالات المنشورة/المسودة

### 5.7 محلل / Analyst
يراجع المؤشرات والأثر والتقارير

### 5.8 قارئ / Viewer
يطلع على البيانات المصرح بها فقط

## 6) مؤشرات النجاح (KPIs) للنسخة الأولى
- زمن إنشاء مشروع جديد أقل من 15 دقيقة
- زمن إنتاج مادة محتوى أولية أقل من 30% مقارنة بالعمل اليدوي
- إكمال إعداد تجربة ثقافية أولية خلال يوم عمل واحد
- اعتماد 1–3 جهات تجريبية داخل السعودية
- استخدام أسبوعي نشط من 60% للفريق الأساسي
- رضا المستخدمين الداخليين ≥ 4/5

## 7) متطلبات وظيفية — قصص المستخدم + القبول

### 7.1 المصادقة والدخول
#### قصة المستخدم
كمستخدم فريق داخلي أريد تسجيل الدخول للوصول إلى البيانات حسب صلاحيتي
#### الشروط
- بريد + كلمة مرور
- Token JWT
- Endpoint لمعرفة المستخدم الحالي
#### معايير القبول
- عند إدخال بيانات صحيحة يتم إصدار رمز وصول صالح
- عند الدخول بدون Token يتم رفض الطلبات المحمية
- عند امتلاك دور غير كافٍ يتم رفض العملية برسالة صلاحية

### 7.2 إدارة المشاريع الثقافية
#### قصة المستخدم
كمدير مشروع أريد إنشاء مشروع ثقافي وربطه بجهة ومتابعة التقدم
#### الحقول الأساسية
- organizationId
- code
- nameAr
- status
- progressPercent
- startDate / endDate
#### معايير القبول
- يمنع إنشاء مشروع بدون جهة أو كود أو اسم
- يدعم CRUD كامل (إنشاء، عرض، تحديث، حذف)
- يدعم فلاتر organizationId / status / q
- يحفظ التواريخ بصيغة قابلة للاستعلام

### 7.3 إدارة المحتوى الثقافي
#### قصة المستخدم
كمحرر محتوى أريد إنشاء مادة ثقافية وربطها بمشروع ولغة ونوع وحالة نشر
#### الحقول الأساسية
- organizationId
- projectId (اختياري)
- title
- languageCode
- contentType
- status
- summary
#### معايير القبول
- دعم CRUD كامل
- فلاتر حسب اللغة/النوع/الحالة/المشروع
- بحث نصي في العنوان/الملخص
- حالات محتوى واضحة: draft, in_review, approved, published, archived

### 7.4 إدارة التجارب الثقافية
#### قصة المستخدم
كمصمم تجربة أريد بناء تجربة وربطها بمشروع وتحديد نوعها ومدتها وحالتها
#### الحقول الأساسية
- projectId
- titleAr
- experienceType
- durationMinutesDefault
- publishStatus
#### معايير القبول
- دعم CRUD كامل
- فلاتر حسب المشروع/النوع/حالة النشر
- حاسبة/محاكاة مبدئية لدرجة جودة المسار (simulate-route-score)

### 7.5 لوحة مؤشرات تشغيلية أولية
#### قصة المستخدم
كمحلل أريد معرفة مؤشرات التنفيذ والمحتوى والتجارب بسرعة
#### معايير القبول
- بطاقات KPI رئيسية
- جداول مختصرة لأحدث المشاريع والمحتوى
- قابلية الربط لاحقًا بمخزن أحداث

### 7.6 مساعد AI للمحتوى
#### قصة المستخدم
كمحرر محتوى أريد مساعدًا يعيد صياغة/يلخص/يقترح صياغات مناسبة ثقافيًا
#### معايير القبول
- إدخال نص + نوع المهمة
- إرجاع ناتج منظم
- حفظ سجل الطلبات لاحقًا (V2)
- تنبيه واضح بأن المخرجات تحتاج مراجعة بشرية

## 8) الصلاحيات (RBAC) — مصفوفة مختصرة
- Projects.read: viewer+
- Projects.write: project_manager / org_admin / super_admin
- Projects.delete: org_admin / super_admin
- Content.read: viewer+
- Content.write: curator / content_editor / org_admin / super_admin
- Content.delete: org_admin / super_admin
- Experiences.read: viewer+
- Experiences.write: experience_designer / project_manager / org_admin / super_admin
- Experiences.delete: org_admin / super_admin

## 9) المتطلبات غير الوظيفية
- بنية قابلة للتوسع عبر وحدات Modules
- قابلية الاستبدال بين DataStore التجريبي وPrisma/Postgres
- توثيق API عبر Swagger
- دعم العربية كلغة أساسية
- تتبع أخطاء مبدئي ومهيأ للـ Observability لاحقًا
- تأمين أساسي JWT + RBAC

## 10) تكاملات المرحلة القادمة
- SSO (Keycloak / Azure AD / Government IAM)
- خرائط/GIS
- إدارة أصول تراث عمراني
- تحليلات زوار من الأجهزة/QR/تذاكر
- تكامل CMS/CRM/Ticketing
- توصيات AI وذكاء ثقافي

## 11) المخاطر والافتراضات
- توفر بيانات ثقافية منظمة محدود في البداية
- اختلاف المصطلحات بين الجهات الثقافية
- الحاجة إلى سياسات نشر واعتماد دقيقة قبل التوسع العام
- الذكاء الاصطناعي يحتاج حوكمة وتقييم انحياز/دقة محلية

## 12) قرارات معمارية (مرحلة التأسيس)
- Monorepo لتوحيد الواجهة + API + الحزم المشتركة
- NestJS للـ API
- Next.js للويب الإداري
- Prisma + PostgreSQL للبيانات التشغيلية
- طبقة Shared لخوارزميات التقييم
- Auth/RBAC داخل API مع قابلية التبديل لـ SSO لاحقًا

## 13) خطة قبول النسخة الأولى (UAT)
1. تسجيل دخول 3 أدوار مختلفة
2. إنشاء جهة/مشروع/محتوى/تجربة
3. تعديل حالة مشروع ومحتوى وتجربة
4. تصفية وبحث
5. اختبار صلاحيات (منع/سماح)
6. مراجعة Swagger
7. توثيق مخرجات التشغيل في تقرير Pilot
