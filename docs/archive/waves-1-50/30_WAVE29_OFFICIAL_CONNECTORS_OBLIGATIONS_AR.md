# Wave29 — موصلات رسمية إضافية + التزامات الامتثال

هذا الإصدار يرفع مستوى قسم الرادار والمنافسات بإضافتين إنتاجيتين:

1) موصلات رادار رسمية أكثر لمصادر سعودية بدل التقاط HTML العام
2) تحويل مصفوفة الامتثال داخل المنافسة إلى التزامات قابلة للمتابعة: مالك، موعد، حالة، تذكير، وربط بسير عمل

## 1) موصلات الرادار الرسمية (Worker)

تم توسيع `apps/worker/src/index.ts` لإضافة موصلات:

- etimad_api
  - موصل تكامل رسمي عبر واجهة Etimad API عند توفرها.
  - يتطلب تمرير رابط حي عبر المتغير `ETIMAD_TENDERS_API_URL` وتوكن عبر `ETIMAD_API_KEY` أو `ETIMAD_BEARER`.
  - عند عدم توفر الرابط/التوكن، يتم تجاهل الموصل بدون أخطاء.

- rcrc_opendata
  - موصل يعتمد على Explore API v2.1 الرسمي لمنصة البيانات المفتوحة للهيئة.
  - يبحث ديناميكيًا عن مجموعات بيانات ذات علاقة (tender / procurement / contract / competition) ثم يحاول استخراج سجلات.
  - إذا لم توجد مجموعات بيانات ذات علاقة، لن ينتج عناصر.

- balady
  - موصل يعتمد على صفحة بلدي الرسمية للمنافسات والمشتريات.
  - يقرأ الصفحة ويستخرج عناوين محتملة بشكل حذر، ثم يفلتر ثقافيًا.
  - في حال عدم القدرة على استخراج عناوين محددة (أو الحاجة لتسجيل دخول)، يصدر مؤشر مجمّع فقط.

### المتغيرات البيئية

- RADAR_CONNECTORS
  - الافتراضي: `etimad_api,etimad,moc,rcrc,rcrc_opendata,balady,ungm`

- ETIMAD_TENDERS_API_URL
  - رابط واجهة الاستعلام عن المنافسات (حسب اعتماد/Etimad عند تفعيلها)

- ETIMAD_API_KEY / ETIMAD_BEARER
  - توكن Authorization للتكامل الرسمي

## 2) التزامات الامتثال (Obligations)

يوجد موديول `apps/api/src/modules/obligations` لتحويل عناصر الامتثال إلى التزامات فعلية:

- لكل التزام: نوع، حالة، مالك، موعد، وصف
- تذكيرات: Reminder rows + Jobs في BullMQ عبر `atheel-obligations`
- ربط تلقائي بسير عمل (Workflow) للمتابعة عند إنشاء/تحديث الالتزام

### التشغيل

1) شغّل Postgres + Redis
2) شغّل API + Worker
3) اضبط WORKER_TOKEN نفسه في API وWorker
4) لتجربة الرادار:
   - جدولة scan من الويب أو عبر API
5) لتجربة الالتزامات:
   - حلّل كراسة منافسة ثم نفّذ Refresh Obligations من صفحة المنافسة
