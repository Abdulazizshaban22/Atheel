# Wave56 — تحويل أَثِيل إلى مشغل عام لكل المجالات مع جاهزية مايكروسيرفس

هذا المستند يحدد كيف نصمم أَثِيل كمشغل عام Multi-Domain Operating Platform، بحيث تبقى النواة ثابتة وقابلة للحكم والقياس، بينما تتغير خدمات المجال حسب القطاع (ثقافة، تراث، عمران، قانون، تعليم، صحة… إلخ).

الهدف ليس تفكيك كل شيء إلى مايكروسيرفس فورًا. الهدف هو هيكلة واضحة تجعل التفكيك لاحقًا قرارًا هندسيًا محسوبًا وليس قفزة خطرة.

## 1) مبدأ المنصة: نواة تشغيل + حزم مجال

### 1.1 النواة Core Platform
النواة مسؤولة عن الأشياء التي لا يجب أن تتكرر في كل مجال:
- هوية وتوثيق وجلسات متعددة الأجهزة مع تدوير Refresh وكشف إعادة الاستخدام
- سياسات وصلاحيات دقيقة Policy Engine
- عزل جهات Multi-tenant + سجل تدقيق Audit + أحداث تشغيل Operational Events
- حزم تسليم Delivery Packets (PDF/PPTX/ZIP) مع بصمة تحقق وتوثيق
- تتبع وتشخيص Observability عبر OpenTelemetry

هذه المكونات مرتبطة مباشرة بأمان الجلسات وإدارة الهوية، وممارسات OWASP تؤكد أهمية دورة حياة الجلسات وإبطالها وتدويرها بشكل صحيح. 

### 1.2 حزم المجال Domain Packs
كل مجال يضاف للمنصة على شكل حزمة واضحة:
- نماذج بيانات المجال
- وحدات API وشاشات
- قوالب تشغيل Workflows
- قوالب تسليم Packets
- مؤشرات قياس أثر

في Wave56 تمت إضافة مفهوم Capability Packs ليكون نقطة تحكم للتمكين والتعطيل لكل مجال داخل كل جهة.

## 2) مخطط جاهزية المايكروسيرفس بدون فوضى

### 2.1 لماذا نحتاج بوابة API Gateway أو BFF
إذا صار عندك عدة خدمات مجال، لا تجعل الواجهة تتصل مباشرة بعشرات الخدمات.
الحل العملي هو طبقة بوابة أو طبقة Backend for Frontend تقوم بالتوجيه والتجميع حسب الشاشة. هذا نمط معروف في الأنظمة الموزعة. 

### 2.2 كيف تدعم NestJS الانتقال إلى مايكروسيرفس
NestJS يدعم نمط المايكروسيرفس برسائل وأحداث عبر Transportات متعددة، مع فصل واضح بين الرسائل والأحداث. 

### 2.3 أمن المايكروسيرفس: هوية موحدة داخلية
عند التوسع إلى خدمات متعددة، أهم نقطة هي نقل الهوية والصلاحيات بطريقة موحدة بين الخدمات، وهذا مذكور بوضوح في OWASP Microservices Security Cheat Sheet. 

## 3) Capability Packs داخل أَثِيل

### 3.1 ما الذي تمت إضافته في Wave56
- جداول قاعدة بيانات:
 - CapabilityPack ككتالوج رسمي للحزم
 - OrganizationCapability لتمكين وتعطيل الحزم لكل جهة
- API جديد:
 - GET /api/capabilities/catalog
 - GET /api/capabilities/me
 - POST /api/capabilities/set

هذه الخطوة تجعل أَثِيل قابل للتركيب، وتسمح أن تكون المنصة مشغل عام مع اختلاف المجال دون أن تتضخم واجهة واحدة للجميع.

### 3.2 كيف يستخدم ذلك عمليًا
- جهة متحف: تفعّل heritage.assets و heritage.iiif
- جهة موسم: تفعّل ops.reliability و compliance.matrix
- جهة تعليم: تفعّل culture.content و ai.rag

## 4) متطلبات تشغيل لا غنى عنها عندما تتحول لموزع

### 4.1 تتبع الطلبات عبر الخدمات
OpenTelemetry معيار مفتوح لتتبع الطلبات والمقاييس عبر الخدمات. كل خدمة لازم تحمل requestId و correlationId وتصدر Traces ومقاييس. 

### 4.2 أحداث بدل الربط المباشر
ربط الخدمات عبر أحداث Domain Events يقلل التشابك.
في أَثِيل، Outbox موجود كأساس موثوق لإرسال الإشعارات والأحداث خارج النظام.

## 5) توصية تنفيذية

تسلسل عملي بدون مخاطرة:
1) إبقاء apps/api كمنصة موحدة مع ضبط الحدود الداخلية عبر Capability Packs
2) استخراج أول خدمة ثقيلة التشغيل فقط (Exports أو RAG أو Radar) إلى خدمة مستقلة لاحقًا
3) إضافة API Gateway/BFF عندما تبدأ الواجهة تحتاج بيانات من خدمات متعددة
